Schedule & worker timesheet — testing guide

For the product owner / client. Plain language. Covers what was added recently: manager Schedule (payroll timesheet), worker Start/End on tasks, and worker Hours (read-only timesheet).

Plan length: test over 2–3 real work days. Start and End must be checked on different days in real time (same-day clock only). A short interval (Start, then End an hour later) is enough — full 8-hour days are not required.

1. Two apps — what each is for

A) Manager app (you / PM)

Desktop-style app after login as project manager or admin.

  • Gantt / Tasks — the work plan (what to build, when, who is on the task).
  • Schedule (menu: Planning → Schedule) — your payroll notebook for the day: where the person goes (project + address), expected hours, optional KM. You assign the project by hand for that day (from memory, notes, or a glance at Gantt). This is not the same system as tasks.

Why separate? Pay days and job-site destinations are your decision for payroll. The app does not invent that from Gantt automatically.

B) Worker app (field crew)

Mobile-first app after login as worker / foreman / contractor (task role).

  • Tasks — today’s work from the plan (Gantt).
  • Start work / End work on a task for today — records actual time with phone GPS near the jobsite (~200 m).
  • Schedule — days you published for them (destination + expected hours); they can also clock there when a row exists.
  • Hours (bottom tab) — monthly read-only timesheet built from tasks + their Start/End. No manual project pick. Different from your Schedule notebook on purpose.
Remember: Manager Schedule ≠ Worker Hours. Same idea (time + place), different purpose — so you are not looking at a duplicate of your own model.

2. What to prepare (once, ~15 minutes)

  1. Project with a real address saved (needed for GPS check).
  2. Task on Gantt covering the next 2–3 days; worker assigned to the task.
  3. In Schedule, for those days: assign that worker to that project; set Expected start/end if you use them.
  4. Worker phone: allow location, open the worker app on site when testing Start/End.

3. Multi-day test plan

Day 1 — morning (on the jobsite)

  1. Worker: open the task for today → Start work.
  2. Expect: Start time is recorded (local time makes sense).
  3. You (PM): open Schedule for that person/day — if you had a row for that project+day, Actual start should appear.
  4. Worker: open Hours — today shows project, address, Start.

Why: proves real clock-in on site and that both your notebook and their Hours can see it.

Negative test (optional, off site / at home): try Start → should be refused (“too far from the job site”).

Day 1 — evening (on the jobsite again)

  1. Worker: same task, today → End work.
  2. Expect: End time recorded; day duration looks right.
  3. You: Schedule shows Actual end (when a row exists).
  4. Worker Hours: Start and End for the day.

Why: start and end belong to the same calendar day and near the same place.

Negative: End off site → refused. End without Start → refused. Other day in the day picker → Start/End buttons not available.

Day 2 — repeat a normal day

Again: Start on site in the morning, End on site later.

  • Hours should show two days with different times.
  • Your Schedule still uses your project picks for payroll — even if that sometimes differs from Gantt (that is intentional in your model).

Why day 2: not a one-off demo — a daily habit.

Day 3 — short check / review

  1. One more Start/End or only review.
  2. Open worker Hours for the month: projects, addresses, total hours.
  3. Open your Schedule: Expected vs Actual.
  4. Try Start on yesterday → should not be allowed.

Why: no backdating past days with the clock buttons.

5. Short “why” (for conversation, not for programmers)

  • Your Schedule — notebook for pay: where they went that day by your decision, expected hours, phone Actuals.
  • Tasks / Gantt — plan of the job.
  • Worker Hours — automatic sheet from plan + their Start/End; they cannot edit it by hand.
  • GPS — Start/End only near the project address (~200 m), so the punch is “on the site”, not from home.
